## 1. Project Goal

Build a **Bitcoin paper trading bot** that:
1. Collects real market data from multiple sources, preferably through Playwright/browser sessions, with no paid data APIs
2. Uses Claude AI (via Anthropic SDK) as an analyst to give a BUY/SELL/HOLD opinion
3. Routes Claude's opinion through a deterministic **risk engine** that has final veto power
4. Executes simulated trades against a fake $10,000 portfolio stored in SQLite
5. Logs every decision, every rejection, and all P&L
6. Once proven profitable on paper, transitions to real money

**The core philosophy**: Claude advises. The risk engine decides. The trader executes.

## 2. Hard Rules (Never Break These)

| Rule | Why |
|------|-----|
| Prefer Playwright/browser data collection — direct Python data calls are technical debt | User is geo-blocked from Binance (451). Browser sessions are more reliable for public sites. Existing direct `httpx` calls in `main.py` should be replaced or explicitly accepted case by case. |
| Claude never directly executes a trade | Claude has a BUY bias. Without a veto layer, it overtrades. Every Claude output must pass through `risk_engine.py` first. |
| Do not add noisy data before risk controls, logs, and backtesting | We already have enough core data to test the trader. More sentiment sources can hide weak logic instead of improving it. |
| Default action is always HOLD | A missed trade is acceptable. A bad trade is not. |
| No paid data APIs | The only paid/official API accepted as core infrastructure is the AI API. |

## 4. Architecture: How a Trade Decision Happens

Every 4 hours (or on webhook/manual trigger), this is the exact flow:

```
get_market_context()          [main.py]
    │   1. Fetches live BTC 15m candles → computes RSI, MACD, EMA, BB, ATR, Stoch, volume
    │   2. Calls _load_daily_context() → reads latest non-null values from:
    │        coinglass.csv (funding, OI, liquidations, ETF flow, L/S ratio)
    │        coingecko.csv (BTC dominance, market cap, altcoin season)
    │        macro.csv (S&P500, DXY, VIX, Gold)
    │        + calculates halving cycle % (static)
    │   3. Fetches Fear & Greed live (alternative.me)
    │   4. Checks USDT/USDC peg live (Coinbase API)
    │   5. Reads events.json (populated by background loop every 15 min)
    │   6. Sets events_unavailable flag if events.json stale/missing
    ▼
_check_data_freshness(context)   [main.py]
    │   CRITICAL issues (price=0, RSI missing, ATR=0, candle > 20min old) → skip scan
    │   BUY_BLOCK issues (events stale/missing) → logged, risk engine enforces
    │   WARNINGs (Fear & Greed missing, master_dataset old) → logged, continue
    ▼
trader.check_trailing_stops(price, atr)   [trader.py]
    │   Checks every open trade before asking Claude
    │   Closes any where price ≤ max(peak − 2×ATR, entry − 1.5×ATR)
    ▼
brain.decide(context, portfolio)   [brain.py]
    │   Calls find_similar(signal, n=20) from matcher.py
    │   Finds 20 most similar historical moments by Euclidean distance
    │   Shows Claude: full context (technicals + derivatives + macro + halving + alerts)
    │   Claude returns JSON: {action, confidence, reason, risk_summary, invalid_if}
    │   If confidence < 60 or JSON is malformed → forces action="HOLD"
    ▼
risk_engine.evaluate(claude_out, market, portfolio, closed_trades)   [risk_engine.py]
    │   Runs 13 deterministic checks in order (see Section 6)
    │   Can override Claude's BUY/SELL to HOLD
    │   Calculates risk-based position size for approved BUYs
    │   Returns: {action, reason, blocked_by, position_usd, stop_price, claude_opinion}
    ▼
trader.buy(price, reason, position_usd, stop_price)   OR   trader.sell(price, reason)
    │   Executes simulated trade in SQLite
    │   Stores stop_price and highest_seen for trailing stop tracking
    ▼
log.info(...)   [main.py]
    Format: "Claude=BUY(72%) → Final=HOLD [blocked:low_confidence] — reason..."
    Every decision is logged. Every rejection is logged with which rule fired.
```

## 5. Data Layer Architecture

Data is organized into 3 layers based on how often it changes:

### Layer A — Critical Override Signals
These can **block all trading** regardless of Claude's opinion. All wired into `risk_engine.py`:
- Max drawdown (portfolio down ≥ 20%)
- Consecutive loss streak (≥ 4 losses in a row)
- Daily loss limit (lost ≥ 5% of starting balance today)
- Stablecoin depeg — live check via Coinbase API for USDT/USDC (> 0.5% deviation)
- Exchange hack/collapse — from events.json populated by CryptoPanic scraper every 15 min
- Events data stale/missing → blocks new BUY only (SELL still allowed)
- FOMC meeting days (hardcoded calendar 2025–2026)
- CPI release days (hardcoded calendar 2025–2026)

### Layer B — High-Impact Context (Daily)
Collected once per day, fed to Claude as context. Available in master_dataset.csv:
- ETF flows (from CoinGlass)
- Funding rate (from CoinGlass)
- Open interest (from CoinGlass)
- Liquidations long/short (from CoinGlass)
- Long/short ratio (from CoinGlass)
- Fear & Greed index (separate scraper)
- BTC dominance (from CoinGecko)
- Altcoin season index (from CoinGecko or calculated from dominance trend)
- USDT market cap (from CoinGecko)

### Layer C — Market Structure (Weekly/Static)
Changes slowly, scraped weekly or hardcoded:
- S&P500, DXY, VIX, Gold (from macro.py via Yahoo Finance)
- Hash rate, total BTC supply, tx volume (from onchain.py via blockchain.info)
- Halving cycle date (static — next halving ~April 2028)
- Twitter account tiers (account_tiers.json — maintained manually)

### Layer D — Live Technicals (Every 4h scan)
Computed live in `get_market_context()` from 15-minute candles:
- RSI(14), MACD(12/26/9), EMA(20/50/200), Bollinger Bands(20,2), ATR(14), Stoch(14,3)
- Volume ratio (current vs 20-period SMA)
- BTC spot price

## 6. Risk Engine — All 13 Checks in Order

File: `risk_engine.py`

### Layer A: Portfolio Safety (blocks ALL trades)
| # | Check | Threshold | Block reason |
|---|-------|-----------|--------------|
| 1 | Max drawdown | Portfolio down ≥ 20% from $10,000 | `max_drawdown` |
| 2 | Consecutive losses | ≥ 4 losses in a row | `consecutive_losses` |
| 3 | Daily loss limit | Lost ≥ 5% of $10,000 today | `daily_loss_limit` |
| 4 | Monthly loss limit | Lost >= 15% of $10,000 this month | `monthly_loss_limit` |
| 5 | Stablecoin depeg | `market["stablecoin_depeg"]` is set | `stablecoin_depeg` |
| 6 | Exchange alert | `market["exchange_hack_alert"]` is set | `exchange_alert` |

### Layer B: Trade-Level Checks (blocks BUY only unless noted)
| # | Check | Threshold | Block reason |
|---|-------|-----------|--------------|
| 7 | Events unavailable | `market["events_unavailable"]` is True | `events_unavailable` |
| 8 | Claude confidence | < 60% | `low_confidence` |
| 9 | Max open trades | >= 3 open | `max_open_trades` |
| 10 | ATR missing | ATR <= 0 | `missing_atr` |
| 11 | Bollinger Band squeeze | bb_width < 0.02 | `bb_squeeze` |
| 12 | Macro event day | FOMC/CPI day AND confidence < 80% | `macro_event_day` |
| 13 | Insufficient cash | < $100 cash | `insufficient_balance` |

**Note**: Checks #4 and #7 block BUY only — SELL is still allowed when monthly loss or stale events block new entries.

### Position Sizing (for approved BUYs)
```
risk_amount  = account_balance × 1%
stop_price   = entry_price − (1.5 × ATR)
stop_pct     = (entry_price − stop_price) / entry_price
position_usd = risk_amount / stop_pct
position_usd = min(position_usd, account_balance × 30%)  ← hard cap
```
This means wider stops = smaller position. Never risk more than 1% of account per trade.

## 7. Data Collectors — How Each Works

### `data/collector/binance.py` — BTC Daily Candles
**What**: 730 days of daily BTC OHLCV candles  
**Why "binance.py" name**: Originally planned for Binance but user is geo-blocked (451 error). Now uses Yahoo Finance.  
**How**: Playwright launches Chromium, navigates to finance.yahoo.com, then calls `page.evaluate()` to run fetch() inside the browser (which has Yahoo's session/cookies set). Tries 3 strategies in order:
1. Yahoo Finance v8 JSON API (`query1.finance.yahoo.com/v8/finance/chart/BTC-USD?interval=1d&range=2y`) — no crumb token needed
2. Stooq.com CSV fallback
3. Yahoo Finance HTML table scrape (last resort)  
**Output**: `data/raw/btc_15m_raw.csv` — 730 rows (despite the "15m" name, these are daily candles)

### `data/collector/coingecko.py` — Market Structure
**What**: BTC market cap, BTC dominance, total market cap, USDT market cap, altcoin season index  
**How**: Playwright navigates to CoinGecko BTC page and charts page, uses `page.evaluate(fetch(...))` to call CoinGecko's internal JSON endpoints with the browser's session cookies  
**Key detail**: Altcoin season index is either fetched directly or calculated from BTC dominance trend (7-day delta): rising dominance → 25, falling → 75, flat → 50  
**Output**: `data/raw/coingecko.csv` — 731 rows

### `data/collector/coinglass.py` — Derivatives Data
**What**: Funding rate, long/short liquidations, open interest, long/short ratio, ETF flows  
**How**: CoinGlass uses webpack — the scraper uses `window.webpackChunk_N_E.push()` to extract the internal `require()` function (`window.__cg_req`), then calls internal module APIs directly. Falls back to `capi.coinglass.com` public endpoints.  
**Key detail**: ETF flow only goes back to Jan 2024 (Bitcoin ETFs launched then). Funding rate perpetual data goes back ~181 days. These are real limitations, not scraping failures.  
**Output**: `data/raw/coinglass.csv` — 2,254+ rows

### `data/collector/fear_greed.py` — Fear & Greed Index
**What**: Daily Fear & Greed index (0–100) from alternative.me  
**Output**: `data/raw/fear_greed.csv`

### `data/collector/macro.py` — Macro Assets
**What**: S&P500 (^GSPC), DXY (DX-Y.NYB), VIX (^VIX), Gold (GC=F)  
**How**: Same Yahoo Finance v8 approach as binance.py, one browser session for all 4 assets  
**Key detail**: 506 rows (not 730) because macro data only covers stock market trading days — correct behavior  
**Output**: `data/raw/macro.csv`

### `data/collector/onchain.py` — On-Chain Metrics
**What**: Hash rate, total BTC supply, transaction volume  
**Source**: blockchain.info public API (no auth needed)  
**Output**: `data/raw/onchain.csv` — 730 rows

## 8. Data Processors

### `data/processor/indicators.py`
Takes raw OHLCV candles, adds all technical indicators using pandas-ta:
- **Trend**: EMA(20), EMA(50), EMA(200)
- **Momentum**: RSI(14), MACD(12/26/9), Stochastic(14,3)
- **Volatility**: Bollinger Bands(20,2), ATR(14)
- **Volume**: Volume SMA(20), volume ratio
- **Binary flags**: above_ema200, above_ema50, ema_bullish, macd_bullish, rsi_oversold, rsi_overbought, high_volume

**Critical fix**: pandas-ta returns different BB column names by version. Always use `[c for c in bb.columns if c.startswith("BBU")][0]` — never hardcode `BBU_20_2.0`.

### `data/processor/labeler.py`
Labels every candle with what actually happened:
- `future_return_1h/4h/24h`: actual % price change after 1h, 4h, 24h
- `hit_tp_before_sl`: did price hit +3% before hitting -1% within 24h? (binary)
- `signal`: BUY/SELL/HOLD label based on rules:
  - BUY: RSI < 45 AND above EMA200
  - SELL: RSI > 60 AND MACD not bullish
  - HOLD: everything else

**Why these thresholds**: Originally calibrated for 15-min candles (RSI < 30). On daily candles RSI never reaches 30 → 0 BUY signals. User set 45/60 which gives BUY:64, SELL:32, HOLD:435, win rate 46.9% (profitable with 3:1 R:R).

### `data/processor/matcher.py`
Finds the 20 most similar historical moments to current conditions using Euclidean distance:
1. Builds a feature matrix from 10 features: RSI, MACD hist, BB width, volume ratio, above_ema200, above_ema50, ema_bullish, macd_bullish, stoch_k, ATR
2. Normalizes each feature 0–1 so all features are equally weighted
3. Computes Euclidean distance from current conditions to every historical row
4. Returns top 20 closest matches with their actual outcomes

This is **evidence for Claude**, not a trading signal. Claude sees: "The last 20 times conditions looked like this, 14 of them hit +3% profit before -1% loss."

## 9. Brain (Claude AI Analyst)

File: `brain.py`  
Model: `claude-haiku-4-5-20251001` (fast and cheap for frequent scanning)

**System prompt philosophy**: HOLD-biased. Claude is an analyst, not a cheerleader. Default is always HOLD. Only deviate if evidence is strong and consistent. Confidence < 60 → force HOLD at prompt level.

**Output schema** (strict JSON — no markdown):
```json
{
  "action": "BUY" | "SELL" | "HOLD",
  "confidence": 0-100,
  "reason": "strongest signal driving the decision",
  "risk_summary": "one sentence on what could invalidate this trade",
  "invalid_if": ["condition1", "condition2"]
}
```

**Defense layers against bad output**:
1. System prompt instructs Claude to output HOLD if confidence < 60
2. `brain.py` JSON parser enforces action must be BUY/SELL/HOLD — else forces HOLD
3. `brain.py` enforces confidence < 60 → HOLD before returning
4. `risk_engine.py` check #7 enforces confidence < 60 → HOLD again (belt and suspenders)
5. Any `json.JSONDecodeError` → returns HOLD with confidence=0

## 10. Trader (Paper Portfolio)

File: `trader.py`  
Database: `paper_trader.db` (SQLite)

**Tables**:
- `portfolio(id, balance)` — single row, tracks cash balance
- `trades(id, side, btc_amount, price, usd_value, reason, timestamp, closed, close_price, pnl, stop_price, highest_seen)`

**Key functions**:
- `buy(price, reason, position_usd=None, stop_price=None)`: Uses risk-engine position size and stop price if provided. Stores `stop_price` and initializes `highest_seen = entry_price`.
- `sell(price, reason)`: FIFO — always sells the oldest open trade first.
- `check_trailing_stops(current_price, current_atr)`: Called at start of every scan. Updates `highest_seen` for each open trade. Closes if `price ≤ max(peak − 2×ATR, entry − 1.5×ATR)`.
- `safety_check(price)`: Legacy safety checks (also covered by risk_engine now).
- `portfolio_summary(price)`: Returns full snapshot: cash, BTC held, unrealized P&L, realized P&L, win rate, return %.

## 15. Key Technical Decisions and Why

### Why Playwright/browser collection over direct Python API calls?
User is geo-blocked from Binance (returns 451). Many useful crypto data routes are paid, rate-limited, blocked, or fragile when called directly from Python. Playwright runs a real browser with normal site cookies and can fetch the same public resources the page itself uses.

Current caveat: `main.py` still uses direct `httpx` calls for some live data. That is known technical debt, not the preferred future pattern.

### Why Euclidean distance for pattern matching?
Simple, deterministic, explainable, fast. No ML model needed. Each historical moment is a point in N-dimensional feature space. We find the closest 20 points to today. Claude then sees what actually happened after those 20 closest moments. The key detail: features are normalized 0–1 before distance calculation so high-magnitude features (price) don't dominate low-magnitude ones (RSI).

### Why FIFO for selling?
Simplest tax-efficient approach. When we sell, we close the oldest open trade first. No picking which trade to close. Consistent and auditable.

### Why Claude Haiku and not Opus/Sonnet?
Haiku is fast and cheap. It runs every 4 hours plus on-demand. At 96 scans/day if you add event-driven scans, Opus would be expensive. Haiku is sufficient for structured JSON output from a well-designed prompt. Upgrade to Sonnet if Claude's signal quality needs improvement.

### Why is the position sizing risk-based?
The old approach (10% of balance per trade) ignores stop distance. If stop is 2% away, 10% position risks 0.2% of account. If stop is 10% away, same 10% position risks 1% of account. Risk-based sizing means: always risk exactly 1% of account, then let the stop distance determine position size. Wide stop = small position. Tight stop = larger position. This is how professional traders size.

### Why double-enforce confidence threshold?
Claude's system prompt says to HOLD if confidence < 60. `brain.py` also enforces this after parsing Claude's JSON. `risk_engine.py` checks it again as rule #7. Three layers because: (1) LLMs don't always follow instructions perfectly, (2) belt and suspenders for financial decisions, (3) the system prompt instruction can drift as conversation history grows.
